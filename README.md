# 《魂坠深境》护符打孔决策器

![运行方式](https://img.shields.io/badge/运行方式-单文件离线_HTML-0f78a7)
![适用阶段](https://img.shields.io/badge/适用阶段-10–15_孔-34b6b2)
![数据存储](https://img.shields.io/badge/数据-仅保存在浏览器本地-475569)

这是一个面向游戏 **《魂坠深境》** 护符打孔系统的非官方辅助工具。

玩家可以用六边形棋盘录入新旧孔位，保存多套目标宝石组合，并通过可调整的概率权重比较不同版图在限定打孔次数内满足目标的可能性。

> [!IMPORTANT]
> 本工具不是游戏官方程序，也没有获得游戏开发商、发行商或 TapTap 的背书。模拟结果来自玩家设定的数学模型，不代表游戏公布概率或对实际结果的保证。

## 灵感来源

本项目的主要设计灵感来自 TapTap 攻略帖：

> [《护符打孔解析，省材料必看！》](https://www.taptap.cn/moment/841752996395093301)

攻略归纳了孔位连通、公共边数量、边缘孔变化以及中心位置等经验规律，并提出先规划最终形状再进行打孔的思路。

本项目没有复制攻略图片或游戏素材，而是将其中的定性经验转化为可修改的权重模型。感谢原攻略作者及参与实测、讨论的玩家。

## 能做什么

- 在由 37 个小六边形组成的版图上点击录入孔位。
- 分别保存旧版图和新版图，支持 10–15 个连通亮孔。
- 建立多套目标组合分页，每套组合可包含多个形状组件。
- 目标形状支持六个方向的旋转，不进行镜像翻转。
- 精确检查当前版图能否无重叠容纳全部目标组件。
- 自定义相邻边、中心孔、换孔数量及增长阶段权重。
- 比较当前目标组合下保留旧版图或新版图的模拟成功率。
- 一次模拟新版图对全部目标组合的成功率和 95% 抽样区间。
- 全部设置保存在当前浏览器的 `localStorage` 中，不上传版图数据。

## 使用方法

1. 在“目标组件”页面新建或选择一套目标组合。
2. 点击六边形绘制一个组件，填写名称和需要数量，然后保存。
3. 根据需要继续保存其他组件，或者创建新的目标组合分页。
4. 分别在“旧版图”和“新版图”页面录入当前的亮孔。
5. 在“概率模型与权重”中确认参数；不确定时可保持默认值。
6. 先点击“检查当前版图”，确认孔数、连通性和当前匹配情况。
7. 设置未来打孔次数与模拟轮数，然后点击“开始概率模拟”。

模拟完成后，页面会同时显示：

- 当前目标组合下旧版图与新版图的成功率；
- 新版图对每一套有效目标组合的成功率排行；
- 抽样结果中最常见的成功版图。

## 使用注意事项

### 概率不是官方概率

游戏没有公开完整的打孔概率。本工具使用的是可编辑模型：公共边越多的空位越容易新增，公共边越少的旧孔越容易移除，并根据用户设置的权重随机抽样。

因此，页面中的百分比只能用于同一组参数下的相对比较，不能理解为游戏的真实成功率。

### 当前 10–14 孔增长模型仍有限制

目前程序在 10–14 孔阶段只模拟两种净变化：

- 保持当前孔数；
- 净增加 1 孔。

如果游戏一次操作实际可能净增加 2 或 3 孔，当前版本尚未完整覆盖这种情况。使用 10–14 孔结果时应把它视为近似分析；15 孔后的纯换孔比较不受这一限制。

### 目标组件只能旋转

游戏操作不允许把宝石形状镜像翻转，因此程序只枚举六向旋转。一个形状的镜像版本若无法通过旋转得到，应当作为另一种独立形状保存。

### 浏览器数据不会自动同步

组件、组合、权重和版图存储在当前页面来源对应的浏览器空间中：

- 本地双击打开的版本与 GitHub Pages 版本不会共享数据；
- 不同浏览器或不同设备不会自动同步；
- 清理网站数据、无痕模式结束或更换域名可能造成已保存内容丢失。

重要组合建议另行截图或记录。

## 哪些情况会严重拖慢计算

计算量大致随以下乘积增长：

```text
目标组合数量 × 模拟轮数 × 未来打孔次数 × 每次目标匹配开销
```

以下情况尤其容易变慢：

1. **保存了大量目标组合分页**  
   点击一次模拟会分别计算新版图对所有有效组合的成功率。组合数量翻倍，耗时通常也会接近翻倍。

2. **选择 30,000 轮模拟并设置很长的打孔次数**  
   例如 `30,000 轮 × 500 次 × 多套组合` 会产生大量状态转移，不适合作为日常快速判断。

3. **一套组合含有许多小组件或大量重复组件**  
   小组件可摆放的位置更多；多个相同组件还需要搜索不重叠的摆放组合。多个单格、双格、短线或小三角形通常比一个大组件更慢。

4. **目标总格数接近 15 且要求恰好用满**  
   程序需要检查更严格的无重叠组合，可能探索更多候选摆放。

5. **当前版图离目标很远或成功概率极低**  
   如果多数模拟不能提前成功，每轮通常都会跑完整个“未来打孔次数”。

6. **同时允许大量旋转后仍存在许多等价位置**  
   程序会去重完全相同的旋转结果，但非对称形状仍可能产生六组方向和大量平移位置。

建议先使用：

```text
2,000 轮、50–100 次、1–5 套目标组合
```

筛选出最有希望的版图或组合后，再用 10,000 或 30,000 轮进行复核。模拟运行期间不要连续重复点击按钮。

## 本地运行

本项目不需要安装和构建工具。

1. 下载 `index.html`。
2. 使用现代浏览器直接打开。
3. 所有计算均在浏览器中完成。

## 发布到 GitHub Pages

这个工具是纯静态 HTML/CSS/JavaScript，适合使用 GitHub Pages 发布。

推荐使用“项目站点”，而不是占用账户唯一的根站点：

```text
仓库名称：talisman-hole-advisor
访问地址：https://<你的用户名>.github.io/talisman-hole-advisor/
```

发布步骤：

1. 创建一个公开仓库，例如 `talisman-hole-advisor`。
2. 将程序文件复制或改名为仓库根目录下的 `index.html`。
3. 将本 `README.md` 一同放入仓库根目录。
4. 打开仓库的 `Settings → Pages`。
5. 在 `Build and deployment` 中选择 `Deploy from a branch`。
6. 选择 `main` 分支和 `/ (root)` 目录并保存。
7. 等待 GitHub Pages 完成部署。

也可以创建名为 `<你的用户名>.github.io` 的仓库，将网站发布到根地址，但每个账户只能有一个这种用户或组织站点。

本项目不依赖 Jekyll，不需要 `_config.yml`。如希望明确跳过 Jekyll 处理，可在发布目录放置一个空的 `.nojekyll` 文件。

## GitHub Pages 快速入门是否适用

[GitHub Pages 中文快速入门](https://docs.github.com/zh/pages/quickstart) **基本适用，但需要针对本项目做三处调整**：

1. 指南示范的是 `<username>.github.io` 用户站点；本项目更适合使用普通仓库对应的项目站点。
2. 指南允许用 README 作为简单站点内容；本工具必须把实际程序命名为发布目录顶层的 `index.html`。
3. 指南中的 `_config.yml` 和 Jekyll 主题步骤不是本项目所必需的。

指南中关于创建仓库、选择可见性、进入 `Settings → Pages`、选择“从分支进行部署”以及等待发布完成的步骤均可以直接采用。

使用 GitHub Free 时，Pages 来源仓库需要设为公开仓库。公开发布前请确认代码中没有私密数据、账号凭据或不希望公开的内容。
